# 設計段階
- 設計段階はユーザーとインタラクティブに実施する
- 要件を、`docs\specification.md`に記述する
- 実装計画、手順を検討し、Beadsのタスクに階層を設けて分解する
- BeadsのタスクIDは、`t-xxx`の形式とする(Taskの頭文字"T")
  - `bd rename-prefix` で変更する
- featureブランチ名は、`feature/t-xxx`の形式とする
  - BeadsIDをブランチ名にする

# 実装段階
- この部分の、１つのタスクの実行を下記のように自動化する

## subagents
1. Beads管理
  - 実装しない、コードを書かない
2. git、github管理
  - 実装しない、コードを書かない
  - PR作成前に必ずテスト成功が必要
3. コーディング
4. テスト
  - 失敗時に直接直さず、修正依頼を返す

## hooks
- コードの編集後にlint
  - 失敗時は、コーディングにエラー内容を返し、戻ってコーディングを継続する
- PR前にtest（ステップ5に該当）

## skills
- /task-start BeadsID
  - BeadsIDを指定して、タスクを開始する
  - 処理フロー
    1. Beads取得
    2. InProgress更新
    3. branch作成
      - BeadsIDがわかればfeatureブランチを特定できる、また逆もできるブランチ名にする
- /task-fix
  - 目的
    - テストエージェントまたは人間レビューで、修正が必要となった場合のループ処理
  - 呼ばれるタイミング
    - テスト失敗
    - PRレビューでNG
    - lint / typecheck NG
  - 処理フロー
    1. 現在のbranchを確認
    2. BeadsIDをbranch名から取得
    3. 修正内容を整理
    4. コーディングエージェントへ修正依頼
    5. テストを再実行
    6. 成功なら終了
    7. 失敗ならretryカウント+1
      - retry値は、エージェント1がBeadsタスクのnotesに、`retry_count: N` として記録する
    8. retryカウントが3を超えたら停止(4回目のNG)
- /task-open-pr
  - 目的
    - テスト成功後のPR作成
  - 処理フロー
    1. branch確認
    2. BeadsID取得
    3. commit作成
    4. push
    5. PR作成
    6. PR本文作成
- /task-close
  - 目的
    - コーディングが正常に終了し、PRがリモートdevにマージされた後のクロージング
  - 処理フロー
    1. リモートdevをローカルdevへpull
    2. エージェント1が、featureブランチで行ったコーディング内容を要約する
    3. エージェント1が、ローカルdevブランチで、Beadsのnotesに追記し、`bd close`でステータスを`done`へ更新する
    4. ローカルdevへcommit
    5. リモートdevへpush
- /task-failed BeadsID
  - 目的
    - 失敗した場合のメンテナンス
  - 呼ばれるタイミング
    - retryカウントが3回を超えた場合(4回目のNG)
    - 人間がPRでマージせず、作業を中断した場合
  - 処理フロー
    1. エージェント1が、該当のBeadsID(Task-A)に対して、
      - ラベルを`failed`に更新する
      - 実施内容と、エラー内容をnoteに追記する
      - `bd close`でタスクをクローズする
    2. エージェント2が、featureブランチにcommitする、pushはしない
      - 失敗した記録を残す
    3. 新タスク(Task-B)を作成し、依存関係を付け替える
      - `bd create` + `bd dep` で実現可能。元タスクの依存関係を `bd dep remove` → `bd dep add` で付け替え
    4. エージェント2が、devをチェックアウトする


## １つのステップ
1. 人間が、BeadsIDを指示して、開始を指示
  - skill: `/task-start BeadsID`
2. エージェント2が、BeadsIDを使ってfeatureブランチを作成し、チェックアウトする
3. エージェント1が、featureブランチで、Beadsのタスクのステータスを`in_progress`へ更新する
  - Beadsファイルもコードと一緒にfeatureブランチで管理される
4. エージェント3が、コーディングをする
  - コーディング終了時のhookのlintチェックでエラーの場合は、エラー内容をエージェント3へ渡し、修正する
5. エージェント4が、テストする。NGの場合は`/task-fix`を実施する
  - エージェント4は、実行したテスト、失敗内容、修正すべき点、再現手順を返す
6. エージェント2が、featureブランチをgithubへpushする。コーディングだけでなく、Beadsの更新内容も含む
7. エージェント2が、featureブランチからリモートdevへのPRを作成する
8. 人間が、PRを確認してマージする。NGの場合は、5.に戻るか、作業を中断する
9. エージェント2が、リモートのdev（マージの結果）をローカルのdevへpullする
10. エージェント1が、featureブランチで行ったコーディング内容を要約する
11. エージェント1が、ローカルdevブランチで、Beadsのnotesに追記し、`bd close`でステータスを`done`へ更新する
12. エージェント2が、Beadsのステータスをローカルdevへcommitし、pushする

## 人間・エージェント間で受け渡すデータ
- 人間→エージェント2: BeadsID
- エージェント2→1: BeadsID
- エージェント1→3: BeadsID、タスク内容(仕様)
- エージェント3→4: 変更ファイルリスト
- エージェント4→3: テスト結果、(NGの場合)エラー内容、修正すべき点、再現手順
